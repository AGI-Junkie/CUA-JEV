## CI implemented

`.github/workflows/ci.yml` runs on pushes, ordinary pull requests and manual dispatch:

1. Python 3.11/3.12 across Ubuntu, Windows and macOS: static checks, unit and platform-neutral integrations, coverage output and JUnit artifacts. UI/MCP dependencies are installed.
2. Required Linux browser job: install Playwright Chromium and dependencies, expose a `chromium` executable, run the full suite, reject unexpected skipped/absent browser suites, and run actual UI plus cross-layout mock-model data flows.
3. `CI acceptance`: an always-evaluated aggregate gate that fails unless both job families succeed. Cancellation, skipped jobs and failures are not accepted as success.

PR jobs have `contents: read`, no model secrets, and `persist-credentials: false` checkout. There is no `pull_request_target`. All model service responses are explicit local HTTP mocks. Screenshots and notes in test artifacts are synthetic controlled-fixture data; no personal desktop screenshot is uploaded.

`pages.yml` is now manual-only. A merge will not accidentally publish the showcase; deployment is separate from this authorization.

The strict browser result validator allows only three named Edge/Excel checks to skip. Missing Chromium/Playwright, omitted critical suites, unexpected skips or failures make the browser gate fail. CI does not hide absent browser coverage behind a green unit job.

## Reviewed fixes and final cloud acceptance

The subsequent findings are now addressed:

- Planner `mode=alternatives` retains the legacy mutually exclusive next-action meaning. Only explicit `sequential` plans reuse ordered semantic steps and persist progress; the compiler offers only the next step's legal routes. Intermediate non-fill actions require their own observable effect before they can be offered.
- Resumed progress must be a unique ordered prefix. Completed input values are freshly read from uniquely rebound controls during compilation and again immediately before input. Cleared, missing or ambiguous prerequisites invalidate the old progress and replan; layout/ref changes with unchanged values still reuse the plan. Prior non-fill effects must also remain independently observable.
- Expected/success conditions accept exactly `kind` and `value`. Malformed types fail safely. Old checkpoints without explicit sequence semantics are rejected instead of guessed.
- Visual success checks use live UIA/DOM text, values or controls, never the same vision model's output. Passive cross-app observations retain identity/geometry/DPI evidence and honestly mark unchecked foreground; desktop actions are withheld until the user reselects its window. ## Run locally in the prepared cloud environment

```bash
.venv/bin/python -m pytest --junitxml=artifacts/ci/browser-tests.xml
.venv/bin/python scripts/check_ci_results.py artifacts/ci/browser-tests.xml
.venv/bin/python scripts/ci_mock_regression.py --output artifacts/ci/data-flow
.venv/bin/python -m ruff check .
```

A fresh Linux environment installs `.[dev,mcp,ui,browser]` and Chromium first. Actions does this automatically. The data-flow runner owns its localhost server and newly created data; it refuses live model mode and does not operate a user's existing session.

For a fresh local workbench installation in this repository checkout:

```bash
python -m pip install -e ".[ui]"
python -m playwright install --with-deps chromium
python -m cua_jev.ui.app --port 8768 --data /tmp/cua-jev-workbench
# Open http://127.0.0.1:8768/workbench
```

The `ui` extra includes Playwright and Pillow; Chromium is a separately installed runtime. The worker records missing dependency/runtime failures as factual failed sessions, allowing a later session after the environment is fixed.
