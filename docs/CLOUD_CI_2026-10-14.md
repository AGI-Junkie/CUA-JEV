## CI implemented

`.github/workflows/ci.yml` runs on pushes, ordinary pull requests and manual dispatch:

1. Python 3.11/3.12 across Ubuntu, Windows and macOS: static checks, unit and platform-neutral integrations, coverage output and JUnit artifacts. UI/MCP dependencies are installed.
2. Required Linux browser job: install Playwright Chromium and dependencies, expose a `chromium` executable, run the full suite, reject unexpected skipped/absent browser suites, and run actual UI plus cross-layout mock-model data flows.
3. `CI acceptance`: an always-evaluated aggregate gate that fails unless both job families succeed. Cancellation, skipped jobs and failures are not accepted as success.

PR jobs have `contents: read`, no model secrets, and `persist-credentials: false` checkout. There is no `pull_request_target`. All model service responses are explicit local HTTP mocks. Screenshots and notes in test artifacts are synthetic controlled-fixture data; no personal desktop screenshot is uploaded.

`pages.yml` is now manual-only. A merge will not accidentally publish the showcase; deployment is separate from this authorization.

The strict browser result validator allows only three named Edge/Excel checks to skip. Missing Chromium/Playwright, omitted critical suites, unexpected skips or failures make the browser gate fail. CI does not hide absent browser coverage behind a green unit job.
